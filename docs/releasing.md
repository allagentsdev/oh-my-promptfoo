# Releasing to npm

The package uses Changesets for version changes and the GitHub-hosted [Publish workflow](../.github/workflows/publish.yml) for npm publication. The workflow checks out a release tag, validates that the tag points at the checked-out commit and matches the package version, runs the full local and packed Promptfoo checks, publishes with npm trusted publishing and provenance, then installs the published version and reruns the consumer and Promptfoo E2E gates. Repeating a successful workflow verifies the existing version and dist-tag without attempting to republish it.

1. Confirm `packages/promptfoo-integration/package.json` contains the reviewed stable version. The initial version is `1.0.0`; for later releases, prepare and merge a Changesets version PR first.
2. Create and push a release-candidate tag at that exact commit, for example `v1.0.0-rc.1`. Dispatch `publish.yml` with `ref=v1.0.0-rc.1`. The workflow stamps `1.0.0-rc.1` only in its working tree and publishes it under `next`.
3. After the candidate's registry consumer and built Promptfoo E2E checks pass, create and push `v1.0.0` at the same reviewed commit. Dispatch `publish.yml` with `ref=v1.0.0`. The workflow first installs and tests the matching `next` candidate, then publishes stable `1.0.0` under `latest` and tests the registry package again.

The npm trusted publisher for `@allagents/promptfoo-integration` must authorize GitHub Actions in organization `allagentsdev`, repository `promptfoo-integrations`, workflow filename `publish.yml`, environment `npm`, with direct `npm publish` allowed. GitHub supplies the short-lived OIDC token; no npm token is stored in the workflow. This is the same publishing authentication used by [AllAgents](https://github.com/allagentsdev/allagents/blob/main/.github/workflows/publish.yml), while Changesets retains this repository's versioning contract.

The package is new, so its first publication may need a one-time authenticated bootstrap before npm exposes package settings for its trusted publisher. Keep that bootstrap to the reviewed release-candidate package and configure the trusted publisher before subsequent workflow publishes. Do not put npm credentials in Git or CI logs. See [npm's trusted-publishing setup](https://docs.npmjs.com/trusted-publishers/) for the current package settings.
